> **JWT 的签名密钥和用户 token 是什么关系？多个用户是共用一个 token 吗？**
>
> 优秀回答：**不是共用**。这里有两个层级的东西：签名密钥 `SECRET` 是**全局唯一**的对称密钥，只存在服务端内存，由环境变量注入、不落库、不设默认值（缺失即启动失败 fail-fast）；而 JWT **是每个用户每次登录实时生成**的，因为它由 Header、Payload、Signature 三段组成，Payload 里携带了该用户的身份信息和 `exp` 过期时间，不同用户 Payload 不同，经 HMAC-SHA256 运算后 Signature 也随之完全不同（哈希的雪崩效应）。
>
> `SECRET` 的作用是**防伪**：签发时用它对前两段做 HMAC 运算得到签名，验证时用同一个 SECRET 重算一遍与 token 携带的签名比对。攻击者即使能任意修改 Payload（base64 编码非加密，谁都能解开），也因不掌握 SECRET 而无法伪造出匹配的签名，篡改必然被识破。
